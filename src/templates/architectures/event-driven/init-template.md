## Principles

- State changes flow as immutable events; consumers project their own read models.
- Producers are decoupled from consumers via a durable broker.
- Eventual consistency is the default; document anywhere strong consistency is required.

## Decisions to record as ADRs

- Event store / broker (Kafka, RabbitMQ, Pulsar, EventStoreDB).
- Schema registry & evolution rules (Avro/JSON Schema/Protobuf).
- Delivery semantics (at-least-once vs. exactly-once) and idempotency strategy.
- Sagas: choreography vs. orchestration.

## Diagrams to fill in during `sdd spec`

- Broker topology (topics/streams, partitions, consumer groups).
- Event-flow / saga diagrams for critical processes.
- Sequence diagrams covering retry / DLQ paths.

## Common pitfalls

- Treating events as commands.
- Tight coupling via shared event payload structure.
- Missing replayability or schema versioning strategy.
