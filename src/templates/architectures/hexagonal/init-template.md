## Principles

- Dependencies point **inward**: `adapters → application → domain`. Domain code knows nothing about frameworks.
- Ports are interfaces owned by the application layer; adapters implement them.
- Tests target the domain & application layers in isolation; adapters get integration tests.

## Suggested package boundaries

| Layer        | Owns                                                                 |
| ------------ | -------------------------------------------------------------------- |
| `domain`     | Entities, value objects, aggregates, domain services, domain events. |
| `application`| Use-case services, command/query handlers, port interfaces.          |
| `adapters`   | HTTP, persistence, messaging, external SDK clients.                  |
| `infra`      | Bootstrap, dependency wiring, configuration, observability.          |

## Common pitfalls

- Domain importing framework annotations or DTOs from adapters → break dependency rule.
- Anaemic domain (logic in services only) → revisit aggregates during `sdd brainstorm domain`.
- One God port → split per use case; ports are tiny.
