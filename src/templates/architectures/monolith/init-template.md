# {{metadata.name}} — modular monolith playbook

> Generated by `sdd init` on {{generatedAt}}.

## Principles

- One deployable, but **module-first internal structure** so future extraction is cheap.
- Each module owns its data; cross-module access only through public APIs.
- Strong static analysis to prevent illegal cross-module imports.

## Decisions to record as ADRs

- Module boundaries (DDD subdomains).
- In-process communication (direct calls, in-memory bus).
- Shared infrastructure (single DB schema vs. per-module schema).
- Path to extraction if/when a module needs to become a service.

## Diagrams to fill in during `sdd spec`

- Module dependency graph (no cycles allowed).
- Data ownership map (which module writes which tables).
- Sequence diagrams for the cross-module flows.

## Common pitfalls

- "Big ball of mud" — modules are folders only, not enforced boundaries.
- Shared mutable state across modules.
- Skipping integration tests because everything runs in one process.
